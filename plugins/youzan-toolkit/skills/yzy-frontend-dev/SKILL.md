# YZY 前端开放规范

## 原则

先读取目标仓库的代码、`AGENTS.md`、`README.md` 和根目录脚本，再查询 `yzy-knowledge-search` 确认开放场景与能力边界。项目代码事实优先，官方文档用于确认平台契约；两者冲突时明确指出，不要猜测。

## 工作流程

1. 确认目标页面和端：消费者端 H5、消费者端小程序、商家后台、商家 App H5 或企业微信助手 App H5。
2. 检查现有目录、相邻实现、页面配置与 Slot 标识。
3. 使用 `yzy-knowledge-search` 查询开放场景、支持端、能力类型和标识。
4. 判断可用能力：Slot、Data、Method、Hook、Event、整页替换或 API。
5. 说明前置条件和证据边界，再做最小代码修改。
6. 使用仓库根目录的 `dev:*`、`build:*` 命令验证；浏览器问题交给 `yzy-browser-debug`。

## 工程规则

- 优先使用仓库根目录公开的命令，不直接猜测或调用底层 `yzc` 命令。
- 开发调试期间不要对同一目标同时执行 `dev` 和 `yzc build`；构建可能清理 `dist` 并中断本地资源。
- `@youzan-cloud/browser-runtime` 只能作为仓库根目录开发工具，不能加入业务子项目依赖。
- 页面生命周期和页面实例能力优先使用现有代码约定的 `this.yz`。
- 如果官方页面环境或现有业务代码使用全局 `yz`，不要直接判定其非法；先检查 Runtime 是否完成页面环境注入，再按官方契约使用。
- 商家端普通模块需要网络能力时，检查当前 `@youzan-cloud/react-cloud-runtime` 版本与导出，不照抄其他应用的项目名。
- 本地请求必须确认开发环境和目标域名，避免误发到正式 `*.isv.youzan.com`。
- OPTIONS 失败先排查目标服务的 CORS 预检，不通过关闭浏览器安全策略规避。

## 回答规则

- 不编造开放场景、Slot、事件、参数或发布步骤。
- 知识库结果不足时明确说明，不用通用前端经验冒充有赞云事实。
- 推荐方案标注为推荐，不描述为唯一官方方案。
- 把“代码已修改”“编译通过”和“页面验证通过”分开报告。
