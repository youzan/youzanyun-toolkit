# YZY 前端场景定制

## 核心职责

辅助完成开放 2.0 定制需求的场景判断和代码落地：先把需求映射到一个或多个开放场景，再按涉及场景读取对应引用文件，随后在目标工程中修改配置和代码。引用文件提供可迁移实现模板，不是通用前端开发指南。

通用前端开发、页面搭建、UI 改造和调试优先交给 `yzy-frontend-dev`；本 skill 只处理前端场景判断、官方能力边界和场景代码模板。

## 工作流程

1. 阅读用户需求，提取目标端、页面身份、URL 变化、局部增强或整页重做、以及是否涉及下单/支付流程。
2. 识别需求命中的一个或多个开放场景；一项需求可以组合多个场景，但只读取当前需要的引用文件，不要一次性加载无关资料。
3. 需要确认能力名称、参数、端支持或版本限制时，使用当前环境可用的有赞云文档检索工具；若存在 `yzy-knowledge-search`，用它搜精确能力名。
4. 读取目标工程现有页面配置、目录和相邻实现，确认页面 key、Slot/Hook 名、组件文件和既有写法。
5. 按场景模板修改配置和代码，新增或调整 `index.js`、`index.json`、`page.vue`、`page.jsx`、Slot 组件或 Hook 注册逻辑。
6. 执行可行的验证；无法验证时说明原因和剩余风险。
7. 只有当用户明确要求“先给方案/示例/不要改代码”时，才停止在方案或代码模板输出。

## 场景路由

一项需求可能命中多个路由；按需读取多个引用文件并组合落地，但只读取与当前需求相关的资料。

- 既有页面上只加 Slot、读页面 Data、调用 Method/Hook/Event，或在商品详情、下单页、待支付页、PC 商家后台页面上增强局部能力：读 `references/extend-page.md`。
- 需要新增一个 URL、新增一张独立页面，包括消费者端页面或 PC 商家端页面：读 `references/create-page.md`。
- 原有页面链接、入口和页面身份不变，但页面内容整体由三方重新实现，包括消费者端或 PC 商家端整页替换：读 `references/replace-page.md`。
- 消费者端下单页 `trade-buy` 或待支付页 `trade-pay` 中断提交、创建订单、支付前确认、支付后处理：读 `references/order-flow-hooks.md`。
## 官方资料使用规则

- 需要确认能力名称、参数、端支持、版本限制或文档最新描述时，使用当前环境可用的有赞云文档检索工具，优先搜精确能力名，例如 `页面定制`、`独立页面 createPage`、`整页替换`、`创建订单前触发`。
- 引用文件中的固定云文档链接只作为兜底来源；如果知识库检索结果与引用文件不一致，以最新官方文档为准，并在回答中说明差异。
- 不编造 Slot 名、Data 字段、Hook 名、Method 名。用户指定未知能力时，先查知识库或目标工程 mock/config。

## 落地要求

- 代码改动保持最小必要范围，贴合目标工程现有结构和相邻实现。
- 配置改动和业务代码改动保持最小必要范围。
- 最终回复说明使用的开放 2.0 场景、修改文件、关键实现和验证结果。
- 如果缺少目标工程、目标页面或能力文档依据，明确说明阻塞点，不用模板代码冒充已落地。
